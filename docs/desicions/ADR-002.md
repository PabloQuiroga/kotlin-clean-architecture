# ADR 002: Uso de Kotlin Coroutines y Flow

## Estado
Aceptado

## Contexto
Las futuras fuentes de datos o persistencias pueden implicar red y disco. La demo actual usa entrada de ejemplo y almacenamiento en memoria, pero mantiene contratos suspendibles y observación reactiva para esos cambios posteriores.

## Decisión
Utilizar **Kotlin Coroutines** para operaciones suspendibles y **Flow** para observar cambios del repositorio. El repositorio serializa las mutaciones con `Mutex` y publica el estado mediante `StateFlow`.

## Justificación
- **Eficiencia**: Las corrutinas son "hilos ligeros", permitiendo miles de tareas concurrentes sin agotar la memoria.
- **Lectura**: Permiten escribir código asíncrono que se lee la manera secuencial, eliminando el "Callback Hell".
- **Estándar**: Kotlin Coroutines es una herramienta estándar del ecosistema Kotlin para desarrollar aplicaciones asíncronas en JVM y otras plataformas Kotlin.

## Consecuencias
- Los métodos del controlador y de los casos de uso son suspendibles; el llamador administra su ejecución.
- La demo de consola usa `runBlocking` en `Main` como scope de vida de la aplicación. Una interfaz con ciclo de vida propio debe usar un scope ligado a ese ciclo.
- El dominio acepta la dependencia de Coroutines para `suspend` y `Flow`; véase ADR-001.
